# BUKLOD Pilot Support Triage

## P0 — Stop / Escalate Immediately

Examples:
- privacy leak
- cross-church access
- privilege escalation
- pastoral-note exposure
- broken account deletion
- data corruption
- mass login failure
- crash blocks core use for many testers

Action:
1. capture minimum necessary evidence
2. do not repost sensitive leaked content
3. enable Maintenance Mode if continued use increases risk
4. assign technical/security owner
5. retest before reopening

## P1 — Major

Examples:
- devotional completion unreliable
- push workflow significantly broken
- leader cannot access assigned group
- pilot access incorrectly denies many valid users
- event attendance workflow unusable

Action:
- assign owner same pilot cycle
- document workaround if safe
- do not expand pilot while critical P1 privacy/access issues remain

## P2 — Normal

Examples:
- confusing copy
- minor feature bug with safe workaround
- inconsistent sorting
- non-critical loading delay

## P3 — Polish

Examples:
- spacing
- icon preference
- minor wording
- non-blocking visual alignment

## Privacy rule for screenshots

When asking a tester for a screenshot, first ask whether the screen contains:
- prayer details
- private reflections
- pastoral notes
- phone/email
- visitor records

Redact unnecessary personal data before sharing the screenshot.
