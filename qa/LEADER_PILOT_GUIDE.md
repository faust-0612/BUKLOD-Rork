# BUKLOD Leader Pilot Guide

## What leaders are testing

Leaders should focus on whether BUKLOD helps pastoral care without turning monitoring
into surveillance.

Test:
- group visibility
- devotional participation indicators
- caring follow-up
- shared reflections
- prayer visibility
- group/community interaction
- learning progress
- event/church-life workflows
- notification wording

## Follow-up standard

A participation signal is a reason to ask, not a reason to accuse.

Preferred approach:
"Kumusta ka? Just checking in. May maitutulong o maipapanalangin ba kami?"

Avoid:
- public ranking
- public shaming
- treating missed activity as proof of disobedience
- recording unnecessary sensitive details

## Pilot data

During technical pilot, use test/demo pastoral notes where possible.

If a real care issue arises, handle it through the church's appropriate pastoral process
rather than assuming the app is the safest record for every detail.

## Feedback

Report both:
- features that reduce leader workload
- features that create unnecessary monitoring burden

BUKLOD should serve discipleship and care; leaders should not become full-time app
administrators.
