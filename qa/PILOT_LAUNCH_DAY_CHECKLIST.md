# BUKLOD Pilot Launch Day Checklist

## 60–90 minutes before access opens
- [ ] Confirm staging environment, not production.
- [ ] Confirm Maintenance Mode is OFF.
- [ ] Confirm Pilot Access Required is ON for controlled pilot.
- [ ] Confirm current testers are Active in the intended cohort.
- [ ] Confirm first System Admin recovery account works.
- [ ] Confirm today's devotional is visible.
- [ ] Confirm Help Center loads.
- [ ] Confirm Pilot Checklist loads.
- [ ] Confirm Send Feedback works.
- [ ] Confirm push notification path was tested.
- [ ] Confirm no open P0 defect.

## Access opening
- [ ] Send Welcome to the BUKLOD Pilot announcement.
- [ ] Give testers the Pilot Tester Guide.
- [ ] Tell testers not to enter highly sensitive real-world test data.
- [ ] Give a clear support contact/channel outside the app.
- [ ] Remind testers that problems should be reported, not hidden.

## First 2 hours
- [ ] Watch login/registration/approval failures.
- [ ] Watch cross-church/group visibility issues.
- [ ] Check feedback queue every 30–60 minutes.
- [ ] Verify at least one Member and one Leader complete the Pilot Checklist.
- [ ] Verify one Android offline/reconnect test.

## End of Day 1
- [ ] Review P0/P1 defects.
- [ ] Decide PROCEED / HOLD / MAINTENANCE.
- [ ] Update release notes if a replacement build is planned.
- [ ] Record pilot decisions in defect/UAT documentation.
