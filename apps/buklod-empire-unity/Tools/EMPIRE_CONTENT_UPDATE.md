# Native Empire content update workflow (DEV only)

Current ABI: empire-audio-v1, Android, Unity 6000.3.29f1, exact configured Android version code. This implementation is restricted to audio; it cannot replace models, maps, animations, shaders, C# or gameplay/reward configuration. No hosted endpoint, key or deployed content revision currently exists in this workflow. Built-in offline assets remain usable without network; next consolidated isolated APK build requires actual pinned trust configuration.

## Once, on the build/signing machine
1. Set up an approved HTTPS static content directory (no redirect; immutable bundles). Check actual capacity and redistribution rights. Do not use the MAIN database, billing or rewards infrastructure.
2. Generate/store an RSA 2048+ private key outside all Git checkouts, with restricted file permissions and offline backup. Never upload or paste it into chat, source, app or host. Example command: `openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out <private-key-outside-repo>`.
3. Run `python Tools/empire-content-sign.py trust --key <private-key-outside-repo> --base-url <actual-https-content-directory-ending-in-slash> --apk-code <actual-Android-version-code>`. Only public key, origin and APK code go in Resources/EmpireContentTrust.json. Review and track the public configuration intentionally.
4. Import the 103 pinned Library files; prepare existing acquired inputs. In pinned Unity Android mode, use BUKLOD Empire / Content updates / Export unsigned audio bundles. This exports all 49 CC0 audio slots in two self-contained bundles. Future replacement asset sources need an approved provenance/hash input change in the editor exporter, not a native player change if ABI stays compatible.
5. Run `python Tools/empire-content-sign.py sign --key <private-key-outside-repo> --unsigned-dir <export-folder> --output <new-publish-directory> --revision <strictly-increasing-integer>`. Copy the immutable content-addressed bundles first, then replace manifest.json last. Never delete the previous known-good bundles before clients have recovered. Do not publish incompatible or unlicensed data.

## Client behavior
Audio Settings → Content Updates: automatic small signed manifest check when connected; explicit Download consent even on Wi-Fi; no mandatory startup network. Max 16 MiB per bundle, 32 MiB per revision, 128 MiB isolated cache, 64 MiB free-space reserve. Two attempts with bounded timeouts; restart to activate; verified completed bundle reuse (not HTTP byte-range resume). Verify RSA SHA-256 signature, exact platform/runtime/ABI/version, per-bundle hashes/sizes, slot allowlist; reject redirects, unknown slots, scene bundles and incompatible audio. Retain prior signed revision and built-in fallback. New audio content can be used by existing skill, reward and accepted menu action slots without another APK after the updater is installed. Unused slots are available for future compatible bindings, not guaranteed to play today.
