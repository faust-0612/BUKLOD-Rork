# Native Empire content update workflow (DEV only)

Current ABI: empire-content-v2, Android, Unity 6000.3.29f1, exact configured Android version code. This implementation supports 49 audio slots plus 17 decorative static model slots: seven structure roles per faction and wood, stone, gold. It cannot yet replace rigged heroes, minions, villagers, creatures, farms, tier-marked pickups, maps, animations, shaders, C# or gameplay/reward configuration. No hosted endpoint, key or deployed content revision currently exists in this workflow. Built-in offline assets remain usable without network; next consolidated isolated APK build requires actual pinned trust configuration.

## Once, on the build/signing machine
1. Set up an approved HTTPS static content directory (no redirect; immutable bundles). Check actual capacity and redistribution rights. Do not use the MAIN database, billing or rewards infrastructure.
2. Generate/store an RSA 2048+ private key outside all Git checkouts, with restricted file permissions and offline backup. Never upload or paste it into chat, source, app or host. Example command: `openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out <private-key-outside-repo>`.
3. Run `python Tools/empire-content-sign.py trust --key <private-key-outside-repo> --base-url <actual-https-content-directory-ending-in-slash> --apk-code <actual-Android-version-code>`. Only public key, origin and APK code go in Resources/EmpireContentTrust.json. Review and track the public configuration intentionally.
4. Import the 103 pinned Library files; prepare existing acquired inputs. After the native APK and updater acceptance gates pass, run the guarded export command below in pinned Unity Android mode. This exports 66 slots across five content-addressed groups (magic, reward, Lux structures, Tenebra structures, resources). Every bundle must be self-contained. Replacement CC0 art/audio can be supplied by an editor-only reviewed source manifest; no native change is needed within this ABI.
5. Run `python Tools/empire-content-sign.py sign --key <private-key-outside-repo> --unsigned-dir <export-folder> --output <new-publish-directory> --revision <strictly-increasing-integer> --base-apk <accepted-apk> --base-receipt <verified-receipt.json>`. Copy the immutable content-addressed bundles first, then replace manifest.json last. Never delete the previous known-good bundles before clients have recovered. Do not publish incompatible or unlicensed data.

## Client behavior
Audio Settings → Content Updates: automatic small signed manifest check when connected; explicit Download consent even on Wi-Fi; no mandatory startup network. Max 16 MiB per bundle, 64 MiB per revision, 256 MiB isolated cache, 64 MiB free-space reserve. Two attempts with bounded timeouts; restart to activate; verified completed bundle reuse (not HTTP byte-range resume). Verify RSA SHA-256 signature, exact platform/runtime/ABI/version, per-bundle hashes/sizes, slot allowlist; reject redirects, unknown slots, scene bundles and incompatible audio. Retain prior signed revision and built-in fallback. New audio content and compatible decorative static models can be used without another APK after the updater is installed and verified. Static models must fit the original footprint, have no behaviours/colliders/animators, and use existing native shaders and bounded mesh/texture sizes. Unused slots are available for future compatible bindings, not guaranteed to play today.

## Mandatory remaining gates
- Confirm actual Unity compilation, RSA/IL2CPP crypto support, AssetBundle import/address aliases, package modules, Android network permissions and persistent storage behavior.
- Run 15 authored protocol tests and six static visual contract tests and full existing tests. Test first install offline, checked offer, valid download, interrupted retry/reuse, tampering, incompatible ABI/version, stale replay, storage shortage, simultaneous clicks, corruption recovery, restart, no player-data loss, exact APK fingerprint. Test on device once with a genuinely hosted signed content revision.
- Rigged models/maps/animations/VFX and gameplay-dependent static props are not yet supported. Static decorative visual catalog updates are implemented at source level, only applied at next match initialization; the active match retains its catalog. No remotely executable code.
- Reconcile divergent branches and final asset rights/bindings, finish 13 hero and faction visuals. No production/RC/build-ready declaration yet.

## Reviewed replacement sources
Place the actual approved source files under Assets/EmpireContentSource/ and create manifest.json with status RIGHTS_AND_SOURCE_REVIEWED and entries containing slot, assetPath, author, license (CC0-1.0), sourceUrl (HTTPS), redistributionReviewed (true), and files (each path, sha256, metaSha256). List every new dependency and its Unity .meta hash. Existing native baseline dependencies only are allowed outside that root. Do not include scripts, plugins, scenes, or new shaders. CC-BY remote content awaits signed attribution delivery; do not mislabel a license. Example slots: coin-collect, lux_tower, stone. The gate is not a substitute for actual rights review or Unity playback. Export and sign a full 66-slot revision; no live deployment by this code.

## Mandatory native baseline and guarded export (2026-11-28)

The current inventory/army/terrain/touch logic is compiled native player code, not a v2 content bundle. Do not sign a content revision as a substitute for installing the corresponding new APK. This is an isolated review-package guard, not production authorization.

Use a real accepted APK and an independently recorded local acceptance receipt (outside the checkout). Fields: sourceCommit (40-character Git SHA), package (org.mzbministry.buklod.empire.review), unity (6000.3.29f1), abi (empire-content-v2), apkCode, apkSha256, trustSha256 (hash of the exact public trust JSON embedded in the APK), signatureVerified, deviceVerified, updaterVerified. Set acceptance booleans only after actual verification; this script verifies consistency of local evidence, not the device itself. No template with fabricated acceptance is supplied. Public trust must be intentionally tracked in the clean source. Never track private keys.

Run locally from the Unity project:

```
python -B Tools/empire-content-sign.py preflight --base-apk <accepted-apk> --base-receipt <verified-receipt.json>
python -B Tools/empire-content-sign.py export --unity <pinned-Unity-executable> --base-apk <accepted-apk> --base-receipt <verified-receipt.json>
python -B Tools/empire-content-sign.py sign --key <private-key-outside-repo> --unsigned-dir <new-export> --output <new-directory> --revision <new-revision> --base-apk <accepted-apk> --base-receipt <verified-receipt.json>
```

The export wrapper checks source compatibility before and after Unity, binds the fresh manifest hash to the native receipt, and signing rechecks it before cryptographic signing. Existing manually exported folders must be re-exported through this path. The diff gate conservatively rejects native paths, executable changes even under supplemental assets, dirty source, divergent ancestry and mismatched runtime/trust/APK. The existing Unity asset gate and signer still validate actual assets and all bundle hashes. A passed preflight is not device acceptance, signing, hosting or deployment. Run local guard tests with `python -B -m unittest discover -s Tools -p test_empire_ota_gate.py`. Hosting and previous revision sequence require separately verified evidence; do not overwrite an existing signed manifest without that check.

## First updater acceptance (isolated review bootstrap)

The first signed revision cannot require updater acceptance before the updater has ever downloaded a real revision. After actual APK signature and offline device acceptance, create the local receipt with `updaterVerified: false`, `reviewBootstrap: true` and `reviewOrigin` equal to the dedicated pinned HTTPS URL ending in `/empire-review/`. Use the same `preflight`, `export`, and `sign` commands above with `--bootstrap-review` on each. The APK/package, source ancestry, trust fingerprint, asset validation and signature gates still apply. The export proof is mode-bound, so it cannot be used for ordinary signing. The resulting local release proof explicitly identifies BOOTSTRAP_REVIEW_ONLY and the pinned origin; never upload the proof or use the bootstrap revision as production content. Host only the signed manifest and immutable bundles at that dedicated review origin, then exercise actual update/download/restart/recovery on the device. Only record `updaterVerified: true` after successful real acceptance and use a fresh normal export thereafter. Native ValidateOnly now also checks Android support, trust, review catalog and the updater component before any build.
