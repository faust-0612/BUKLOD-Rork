## Realtime transport foundation — DEV
Input scheduling now accepts strictly increasing ticks inside a four-tick lead window (up to 400 ms), bounded at four frames per participant; stale/duplicate input is rejected, movement expires after three ticks, reconnect clears pending input but preserves accepted sequence. Version 1 binary protocol uses explicit little-endian fields, strict UTF-8, 256-byte client frames and 64 KiB snapshots, rejects trailing bytes and malformed frames. Single-use 256-bit tickets are stored by hash, match-bound, 30-second expiry and replaced per account. Idle leases expire after 15 seconds; the authenticated transport must obtain a fresh ticket on reconnect. The server endpoint accepts an upgraded WebSocket, limits concurrent sockets/auth requests and input frames, marshals authority to a bounded owner-thread queue, uses send/handshake deadlines and sends full fog-filtered snapshots. Client transport requires wss and sends the ticket in the initial binary frame, not a URL. Server-side Auth candidate uses Supabase GET /auth/v1/user with bearer + publishable key (no service-role), rejects MAIN project and anonymous users, has timeouts and bounded body; no Auth calls were made. Dedicated room driver requires ten connected slots before starting and stops on excessive simulation lag; no settlement on host fault. Still required: actual HTTPS/WSS listener and TLS ingress, lobby/matchmaker, snapshot decoder/renderer, adaptive input lead, final-result retention, reconnect grace/bot policy, server persistence, real isolated Auth environment and full E2E tests. Four new EditMode networking tests plus bounded lead test are authored, not executed; the golden wire fixture was independently encoded as bytes in JS. No claims of successful networking or actual authentication.

## Lobby and online state presentation — DEV
Added a single-owner-thread bounded lobby directory: targeted private invites, independent regional casual/ranked FIFO queues, ten members with 5+5 teams, captain ban intents (casual only), unique picks, immutable reservation request, and explicit pending/reserved/handoff states. Verified durable backend reservation is required before handoff; ambiguous outcomes must stay pending. This is not yet a persistent lobby service, rating-based matchmaking, or a live reservation adapter. Added version-1 bounded snapshot decoder, typed client snapshots and a visibility-safe interpolation timeline. An opt-in online presentation component resolves approved actor prefabs and immediately hides absent units; no local match advances. It is not wired into a scene or the existing mobile HUD, does not yet render camp/resource/drop/skill events, and cannot use unapproved catalog art. Added an injected ticket-provider connection coordinator with a four-retry backoff, fresh grant on reconnect, monotonic input sequence and no replay of queued actions. Pre-start server input is rejected and liveness snapshots refresh every two seconds. Client still requires an actual authenticated ticket provider and public WSS listener; final result retention, rating policy, match creation/reservation worker, settlement, scene/HUD and actual multi-client tests remain. Five new EditMode tests authored, not executed. No live writes, deployment or APK.

The reservation request explicitly carries ban-paying captain identities. ReservedRoomHost can construct a single match only from a trusted confirmed reservation; failed construction leaves the reservation intact and room membership is not released until a trusted worker has durably settled or refunded it. This is in-process handoff, not a database reservation implementation. The client now clears its visible timeline and pending inputs immediately upon detecting socket loss. The local environment check found Node and Python but no Unity Editor, dotnet, csc or mcs. The new C# tests are unexecuted.

Host overload or disposal now invalidates outstanding tickets and all active leases, so a frozen match cannot keep clients indefinitely alive on duplicate snapshots. Faulted matches still require a trusted refund/recovery worker; they do not auto-settle rewards.
