## Implementation order and mandatory acceptance
1. Refactor shared simulation into a server-controlled match with 10 explicit participant slots. Offline adapter drives the same rules with one human and bots; no loss of existing hybrid economy/combat mechanics. Preserve canonical 13 heroes, total faction elimination, reinforcement cutoff, draw rules, physical workers, resources and buildings. Test deterministic fixed-tick replay and multi-participant ownership.
2. Auth/session adapter: authenticate existing BUKLOD identity server-side; short-lived match grants bound to account, match, slot and protocol revision. No client service-role keys, secrets or claimed user IDs as authority. Isolated test configuration; no MAIN changes without separate approval.
3. Lobby, invites, private rooms, casual and ranked matchmaking, region/latency selection and draft reservation. Validate distinct hero picks and per-team bans, reserve matching stones atomically, cancel/expire/refund once. Offline practice never consumes persistent stones.
4. Authoritative realtime transport over encrypted connections; simulation server owns timing, random seed, targeting, hits, health, cooldown, XP, AI, resource stocks, trades, upgrades and victory. Client sends bounded input intentions only, never reward or damage results. Use monotonic per-session input sequence, bounded queues and payloads, input rate limits, replay rejection, server-derived actor ownership, time-window validation. Snapshot/delta streams must filter hidden opponent state and support full snapshot recovery; reliable control messages for draft, reconnect and settlement. Choose transport and hosting only after measured latency/load and zero-budget feasibility.
5. Unity online adapter: render server snapshots, interpolate remote actors and use bounded local prediction/reconciliation for movement. Existing touch controls emit commands in online mode. Pause local UI without pausing shared match. Reconnect with fresh auth, server-owned slot, full snapshot and explicit input reset; bot takeover/forfeit policies and stale-input expiry. Never silently turn a disconnected ranked match into rewarding offline play.
6. Transactional server integration: reconcile existing Character System and claimed BP authority with staged candidate schemas. Sacred Stones, trades, Kingdom hooks, character XP/items/mastery and graded arena BP settlement via verified server evidence only. Idempotent finalization, retry/recovery ledger and strict access boundaries; no offline rewards, no QMP/cash or ministry-ledger changes from arena performance. No payment-derived combat advantage. Deploy to a separately authorized isolated test environment only after disposable DB and concurrency tests.
7. E2E acceptance: 10 distinct authenticated clients in a real match; verify movement, all action categories, fog-of-war, authority/replay abuse rejection, lag/loss, disconnect/rejoin, match completion and exactly-once settlement; verify no duplicate or cross-account writes. Run existing offline regression tests and full visual/audio review. Test server cost/throughput; real hosted multiplayer may require recurring compute/bandwidth and is not promised free at arbitrary usage.
8. Final APK: include both modes in native Unity Android ARM64 project; production builds must have approved assets and exact package, secure environment configuration and all online gates. Isolated online RC/test build must have separate package and test backend, not live MAIN. Verify actual APK signature, package, native libraries, installed device behavior and end-to-end online connectivity. Do not describe an offline test as full online-capable delivery.

No network deployment, hosted database changes, Unity build or purchase authorized by this contract alone. Source readiness does not equal online functionality.
