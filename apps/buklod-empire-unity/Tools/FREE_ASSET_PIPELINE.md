# Zero-cost production candidates
Original procedural geometry is checked in under Tools/AssetCandidates, outside Unity's Assets directory. Seven GLB files contain 3 map mesh groups, 4 faction structures, 10 minion roles and 12 villagers. The models are independent geometry candidates, not scanned artwork or visually approved premium models. The map uses the canonical 320 x 220 bounds and original lane/cover positions. No third-party assets, paid AI requests or cloud builds were used to create them.

Regenerate with node Tools/generate-free-candidates.mjs (from any working directory). The checked-in manifest records the exact Git blob IDs and triangle counts. Import only in a separate review workspace; do not move these files into the production catalog until topology, art likeness, rigging, clips, PBR material refinement, collisions and actual Unity visual/device tests pass. The hero baseline is generated by the existing Tools/intake.py; do not duplicate or mislabel it. Keep pending-rights private assets separate. The production guard is unchanged.

## Preparation without paid tools
- `node Tools/prepare-faction-review.mjs` verifies the seven committed GLB blob hashes and extracts 22 individually named, origin-normalized static models into git-ignored Tools/ReviewOutput/factions. The splitter was exercised against both committed faction packs: 11 models each.
- `python Tools/prepare-hero-review.py` reuses the original rigged hero generator and adapts six reference palettes plus all 13 canonical Sacred Stone colors on the chest emblem. It is source-ready, not yet executed in the Unity cloud environment. No synthetic output is approved.
- For actual Unity integration, import a candidate into a separate review project or ignored path and confirm glTF handedness, world bounds, skin deformation, animation controller and URP material quality. Only verified assets move to Assets/Production and receive a rights/art receipt. Existing production gate remains mandatory.
