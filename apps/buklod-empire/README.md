# BUKLOD Empire — separate native Android DEV app
Package org.mzbministry.buklod.empire. Uses official Godot 4.7.2 AAR with native Android Gradle only. The APK contains the canonical Godot game project as root Android assets (no startup pack overrides). Carries the reviewed 13 heroes, 52 pose atlases, 70 sound cues, 42 Kingdom class artworks, 22 public CC0 models including 2 rigs, Arena combat and Kingdom, House, Community scenes. No React Native/Expo/MAIN bundle. 3D is still an exploration preview, not a completed ranked 3D game.
DEV signing uses the runner's debug key; not a durable release signature. No production deployment, OTA, or change to MAIN.

## Reward and account boundary
No isolated Supabase project. The existing BUKLOD MAIN project remains the sole authority for auth, character identity/level, Circle Rank, BP, QMP, inventory, collectibles, diamonds, property and ranked settlement. This first installable offline DEV APK contains no account credentials and grants no real rewards. Existing special-character unlocks and reward eligibility are NOT inferred from local gameplay. Before introducing online rewards, integrate normal Supabase Auth against the same project, account-scoped read-only existing RPCs, and only audited server-authoritative match/reward endpoints with replay protection and verified settlement. Do not import unauthenticated local progress or copy the MAIN ledger. MAIN game removal is a separate step after verified Empire readiness and account/reward parity.

## Native content updates (protocol 1)
Version 0.1.1-dev includes an immutable APK bootstrap, cumulative ZIP overlay, RSA-SHA256 signed manifest, exact native runtime/base/channel matching, bounded HTTPS downloads, one retry, private storage, atomic state, interrupted-boot rollback and explicit rollback. No forced restart during gameplay; activate on normal next launch. No update replaces the bootstrap, session shell or manifest trust root. Resource deletion and native changes require a new APK.
The DEV channel is disabled unless the build receives the permanent public key via repository variable BUKLOD_EMPIRE_DEV_OTA_PUBLIC_KEY. Staging and production require separately controlled keys and immutable native channel identities. The planned read-only origin is the existing MAIN Supabase project /storage/v1/object/public/empire-updates/<channel>/; no bucket or backend mutation was made. Never embed the private signing key. Use scripts/build-buklod-empire-ota.mjs with the baseline receipt of the installed APK, prepared candidate assets, monotonically increasing sequence, output folder and owner-controlled signing key file. Upload content-addressed ZIP before signed manifest only after release QA. No real live publication until trust key and storage path verified.

## Owner-signed 0.1.2 DEV trust provisioning
The OTA runtime is bundled; QA APKs are explicitly not release candidates. The release gate requires a durable independent Android signing certificate and RSA OTA public key, owner-controlled private key, isolated dev path by APK baseline, and a verified dedicated bucket (32 MiB cap, public reads of signed packages only, no client writes). No service-role secret is embedded or uploaded to CI. Run `scripts/setup-buklod-empire-dev-trust.sh` on the authenticated owner's trusted machine with the pre-protected GitHub environment `buklod-empire-dev` and an owner-authorized existing MAIN Storage credential in BUKLOD_EMPIRE_STORAGE_SERVICE_KEY. It provisions via Storage REST API and refuses replacing existing signing identities. Back up the generated keys outside Git. Owner-signed build requires the protected workflow on the Empire branch; a candidate is NOT remotely OTA verified until the owner publishes a harmless signed canary with `node scripts/buklod-empire-storage.mjs publish-dev <baseline> <signed-dir>` and verifies staged/ready receipts after relaunch. Use only one authorized publisher. No new project or live economy change. No production deployment. The current Android QA uses isolated AOSP emulator and a strict nonblank screenshot gate.
