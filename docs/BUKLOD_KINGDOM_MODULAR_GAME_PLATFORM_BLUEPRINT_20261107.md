## 1. Product structure and priorities
BUKLOD App -> existing Kingdom Map -> 13 Character Game Centers -> 39 games in the R1 catalog.
Each center contains three games: ONE existing source game, two additions. Christian's Bible Crown is the first pilot. The 39-game R1 catalog is a finite roadmap, not a claim that 39 games are already implemented.
Possible future content beyond 39 is an optional second release; never replace original games silently.
The Kingdom is not BUKLOD Empire; there is no mandatory engine bridge, map change, direct Empire-to-Kingdom save migration or shared simulation.
Character themes must be connected to the canonical traits and station environment. Existing art, names and IDs take precedence over generic arcade reskins.

## 2. Reusable architecture
A. Game catalog: machine-readable 13-center/39-game manifest; one stable ID for each game. Each record marks existing/pilot/planned status, genre, level policy and native/web compatibility.
B. Center shell: character identity, clear game chooser, local/download state, best record, tutorials, audio/accessibility controls, loading/error/retry, resume.
C. Shared game runtime: stage, lifecycle (ready/play/pause/result), gesture/controller input, haptic, sound, animation, telemetrics, safe teardown.
D. Genre modules (independent deterministic rules; no generic quiz-card fallback for non-quiz mechanics):
  1. quiz/trivia (Bible Crown, Guessing Quest);
  2. board/turn-based (chess with legal moves, castling, en passant, underpromotion and draw rules; checkers, domino);
  3. word/letter/puzzle;
  4. grid/block/number/match-and-merge;
  5. simulation/resource strategy;
  6. movement/rhythm with precise event timestamps.
E. Presentation: Skia/Reanimated for native when available, lightweight Expo web rendering, reusable transitions, original audio/music loops, character animation, particles and responsive touch.
F. Downloadable MEDIA packs: versioned hashes and manifests, HTTPS, atomic cache-write, integrity checks, quotas, LRU eviction, Wi-Fi/data preference, offline fallback and content rollback. Do not download untrusted executable JS or treat an asset as executable code. Binary/native engine upgrades require compatible store builds.
G. Account-scoped preview storage -> validated cloud progress -> approved Character V2 reward service. Do NOT silently reuse globally keyed legacy preview data across accounts.
H. Ads: independent game result/lobby ad opportunities, never during gameplay and never automatic from a game on-screen button without a valid natural break. Explicit user-initiated rewarded video only for non-cash/non-redeemable cosmetic benefits.

## 3. Progression, economy, account integrity
- Distinguish game score, Kingdom mastery/collection, Character Points/level, Circle Rank and cash/redeemable economy.
- Offline/pilot scores are local account-scoped preview data ONLY; no XP, Circle Points, Character Points, paid tokens, Bayanihan balance, referral rewards or money can be granted.
- Production first-clear rewards need a server-owned policy definition; do not trust client-supplied score, firstClear, level, stars, session ID or timestamp. Backend validates canonical game version, level completion, anti-cheat proof and eligibility; grants at most once per user/game/milestone by UNIQUE constraints/idempotency key and SQL transaction/RPC with RLS.
- Replay remains meaningful via best score, mastery, cosmetic upgrades, challenges, and local records; repeating trivial answers MUST NOT farm economy.
- Changing active Character must obey server Character Selection V2 atomic Level-1 reset and independent per-character progress, without resetting existing Circle Points. Existing Special Character gates stay protected. Do not infer Character level from lifetime points.
- Account isolation and deletion: users see only own saved results; logout/switch clears in-memory cache; deletion purges or anonymizes relevant records by retention rules.
- Offline queue: stable local receipt, retry with exponential backoff and bounds, server de-duplication, reconciliation of already-applied receipts, no premature reward banners.
- Audit record: user_id, character_id, game_id, build/version, session/attempt_id, result, reason, source, rewarded_status (if any), created_at; log minimally and avoid private content.

## 4. Monetization contract
- Ad format: passive sponsor/banner only in safe game lobby/result surfaces; interstitial only AFTER completed natural session with cadence control, no interference with timing, answer flow, pause or retry; rewarded ONLY opt-in for cosmetic game benefits, never directly a BUKLOD redeemable benefit.
- Before any activation, reconcile src/lib/buklodGlobalAdController.ts, whose sensitive route list currently includes /games; do not bypass the safety controller globally. Add dedicated route/state-gated game ad policy, protected from exam/classroom routes and underage-sensitive surfaces, integrated with official AdMob consent and kill switches.
- Ad failure/no-fill is always non-blocking. Ad views cannot be a prerequisite to save progress or complete an attempt.
- No autoplay audio before user intent where platform disallows it; independent music, SFX and haptic controls.
- License assets; no copying copyrighted TV-show identity, music, voices, interface or trademark. Mechanic inspirations are permitted, but all branding is original.

## 5. Media and performance budgets (planning targets, NOT actual measured results)
- 60 fps preferred; adaptive quality levels with 30 fps floor on supported lower-tier targets where necessary. Measure frame time p95/p99 and interaction latency, not cosmetic FPS alone.
- Typical 2D/2.5D individual media pack proposed 5–25 MB *before real measurement*; pack varies by art/music. Initial APK does not include every optional media pack.
- Load only selected game's scene; pause/unmount offscreen animations, release textures and audio players, cap sound polyphony, prebuffer short local effects, show graceful loading states.
- Pause/background/phone call: freeze game time, mute/duck audio as appropriate, restore precisely; no phantom errors or duplicate completion.
- Weak connection: playable from complete cached pack; stream no per-frame game calls; short timeout and retry on manifest/download, retry only missing asset bytes, checksum and atomic swap, never discard verified previous pack.
- Accessibility: EN/TL, large touch targets, reduced motion, contrast, optional audio/haptics, captions where practical, input accessibility.
- Instrument downloaded bytes, cache hit ratio, peak RAM, startup p95, audio readiness p95, crash/ANR, no-fill, completion vs exit.

## 6. Complete per-game feature contract
Every release candidate MUST provide:
- An intentional mechanic and character ability connection, objectives, explicit complete win/loss rules, deterministic scoring, tutorial and instructions;
- Start, pause, resume, restart, abandon, result, previous-best and replay; return to the SAME character's center and then the unchanged Kingdom map;
- Difficulty/levels that meaningfully vary rules; no fake Expert label; bounded time and fairness;
- Responsive touch and (where appropriate) keyboard/mouse; safe-area and tablet/web sizing;
- Character art/motion, original and volume-controlled music+SFX, interaction feedback, victory/failure animation, graceful no-audio fallback;
- Stable offline behavior and safe account-isolated save; no duplicate results;
- Per-game deterministic rule tests, platform smoke, poor network/interruption tests and battery/RAM regressions;
- Ads only at approved breakpoints. NO paid boosts affecting fairness or BUKLOD rank.
